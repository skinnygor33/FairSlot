# Message contract: web tier ↔ Erlang back-end

> **Status: DRAFT v0.2** — proposed by Roger, to be reviewed by Macarena.
> Change it freely, but bump the version and tell the other person: both sides code
> against this file.
>
> - v0.1 (20 Nov): first draft.
> - v0.2 (23 Nov): event `slot_taken`, so open calendars update when someone else takes a slot.

The web tier (Java) joins the Erlang cluster as a **hidden node** through JInterface
and exchanges plain Erlang terms with the back-end. Inter-node messages between Erlang
nodes (replication, 2PC, election) are **not** in this file; they are internal to the
back-end, except that they also carry an epoch (proposal §5).

## 1. Conventions

| Thing | Erlang type | Example |
|---|---|---|
| Request ID | binary, UUID assigned by the web tier | `<<"3f2a9c1e-5b7d-4e8a-9c21-7d4e5f6a8b90">>` |
| User ID | binary (the login username) | `<<"alice">>` |
| Resource ID | binary, `room:<building>-<room>` or `equip:<pool>-<item>` | `<<"room:B1-101">>`, `<<"equip:proj-03">>` |
| Time | integer, **milliseconds** since Unix epoch, UTC | `1795680000000` |
| Slot | identified by resource + start time; slots are **1 hour** long and start on the hour | |
| Hold / booking / offer IDs | binary, generated by the back-end | `<<"h-17">>` |
| Epoch | non-negative integer | `3` |
| Free-form fields | map with **atom keys** | `#{expires_at => 1795680300000}` |

Node names: Erlang nodes `fairslot_a`, `fairslot_b`, `fairslot_c`; web tier `fairslot_web`.
All share one cookie (set per environment, never committed).

## 2. Request and reply

The web tier sends every request to the process registered as **`fairslot_gateway`** on
the node it believes owns the resource (see §4):

```erlang
{fs_req, ReqId, Epoch, From, UserId, Op}
%% ReqId  :: binary()      unique per user action; reused unchanged on retries
%% Epoch  :: integer()     epoch of the partition map the web tier used to route
%% From   :: pid()         JInterface mailbox that waits for the reply
%% UserId :: binary()
%% Op     :: tuple()       one of the operations in §3
```

The back-end answers exactly once, to `From`:

```erlang
{fs_reply, ReqId, Result}
%% Result :: {ok, Map} | {error, Reason}
```

**Duplicates.** If a request with an already-processed `ReqId` arrives (the web tier
retries after a timeout or a failover), the owner returns the **stored** result and does
not apply it again (proposal §4, "Duplicate requests").

**Timeout.** The web tier waits 5 s for a reply, then refreshes the partition map and
resends once with the same `ReqId`. A second timeout returns HTTP 503 to the browser.

## 3. Operations

| Op | Sent to | `{ok, Map}` contents | Possible `{error, Reason}` |
|---|---|---|---|
| `{availability, ResId, DayStart}` | resource owner | `#{slots => [#{start, state}]}`, `state` ∈ `free \| held \| booked \| mine` | `not_found` |
| `{hold, ResId, SlotStart}` | resource owner | `#{hold_id, expires_at}` | `slot_taken`, `quota_exceeded`, `not_found` |
| `{release, HoldId}` | resource owner | `#{}` | `not_found` |
| `{confirm, HoldId}` | resource owner | `#{booking_id}` | `hold_expired`, `not_holder`, `not_found` |
| `{cancel, BookingId}` | resource owner | `#{}` | `not_holder`, `not_found` |
| `{check_in, BookingId}` | resource owner | `#{}` | `too_early`, `too_late`, `not_holder`, `not_found` |
| `{join_waitlist, ResId, SlotStart}` | resource owner | `#{position}` | `slot_free`, `already_waiting`, `not_found` |
| `{accept_offer, OfferId}` | resource owner | `#{booking_id}` | `offer_expired`, `quota_exceeded`, `not_found` |
| `{decline_offer, OfferId}` | resource owner | `#{}` | `not_found` |
| `{quota}` | coordinator (its gateway forwards to the user's quota shard) | `#{used_hours, limit_hours, week_start}` | — |
| `{book_bundle, [{ResId, SlotStart}]}` | coordinator | `#{bundle_id, booking_ids => [binary()]}` | `{slot_taken, ResId}`, `quota_exceeded` |
| `{partition_map}` | any node | see §4 | — |

Errors that any op may return:

| Reason | Meaning | Web tier reaction |
|---|---|---|
| `{wrong_owner, CurrentEpoch}` | this node does not own the resource (any more) | refresh map, resend same `ReqId` |
| `stale_epoch` | request routed with an older epoch | refresh map, resend same `ReqId` |
| `no_majority` | node is in a minority partition and stopped serving | try another node |
| `{bad_request, Text}` | malformed op (e.g. slot not on the hour) | HTTP 400 |

Quota handling stays **inside** the back-end: on `hold` the resource owner reserves the
hours on the user's quota shard first (proposal §4). The web tier never talks to the
quota shard except for `{quota}`.

## 4. Partition map and routing

```erlang
%% reply to {partition_map}
{ok, #{epoch      => 3,
       coordinator => 'fairslot_a@vm1',
       partitions => #{<<"rooms-B1">> => 'fairslot_a@vm1', ...},
       resources  => #{<<"room:B1-101">> => <<"rooms-B1">>, ...}}}
```

The web tier fetches the map at start-up and after any routing error, and sends each
request to `partitions(resources(ResId))`. Before the coordinator exists (week 1), a
single node answers with every partition mapped to itself.

## 5. Events pushed by the back-end

The back-end pushes events to the mailbox registered as **`events`** on the web node:
`{events, 'fairslot_web@<host>'} ! {fs_event, Type, Map}`. The web tier forwards them over
WebSocket to the affected user's browsers.

| Type | Map | When |
|---|---|---|
| `offer` | `#{user, offer_id, resource_id, slot_start, expires_at}` | a waitlisted user gets a timed offer |
| `offer_expired` | `#{user, offer_id}` | offer not accepted in time; passes to the next user |
| `hold_expiring` | `#{user, hold_id, expires_at}` | 1 min before a hold expires |
| `hold_expired` | `#{user, hold_id}` | hold released |
| `checkin_missed` | `#{user, booking_id}` | no check-in 15 min after start; slot released |
| `slot_freed` | `#{resource_id, slot_start}` | any slot becomes free (refreshes open calendars) |
| `slot_taken` | `#{resource_id, slot_start}` | a free slot is held or booked (refreshes open calendars) — *added in v0.2* |
| `partition_moved` | `#{epoch, partition, node}` | failover; web tier refreshes its map |
